# Bounded web access for the continuing instance

Status: original investigation and proposed implementation, 2026-09-27. The
[implemented first version](web-browsing.md) now provides opt-in retrieval;
the controls below remain the design target where the implementation differs.
No existing instance is automatically granted network access. Code inspection
used DMN base `0bd9ff5` and upstream Open WebUI tag `v0.11.0`; upstream inspection
is not a verification of the locally installed WebUI environment.

## Recommendation

Give DMN a small, asynchronous retrieval service with its own enforced policy,
durable request ledger and external-result format. Start with public HTML/plain
text retrieval and local paging. Add search through a provider interface later.
Open WebUI can remain the conversation interface and could supply a search
provider behind that service, but should not own the instance's browsing loop.

This fits [outside interaction](outside-interaction.md): the instance can follow
its own interests without a person approving every page. Host network allowances
and site restrictions define the available environment. A page cannot change
those allowances, adopt a prompt revision or authorize another capability.

| Option | Benefit | Cost for DMN | Assessment |
|---|---|---|---|
| Enable WebUI's ordinary search/RAG/tool loop | Existing search providers, extraction and UI | Conflicts with DMN's deliberate payload bypass and continuous inference; needs a separate event adapter anyway | Do not use as the runtime integration |
| Call a WebUI loader through a dedicated adapter | Reuses extraction engines and provider configuration | Version/configuration coupling; outbound subrequests and retries still need DMN accounting | Possible optional backend after conformance tests |
| DMN retrieval service using an established HTTP client and parser | Independent lifecycle, uniform quotas/provenance, small initial surface | DMN must implement and maintain transport safety and recovery | Recommended first implementation |

Owning the policy does not mean writing a browser engine, TLS stack or search
engine. Keep HTTP/extraction dependencies optional so the core retains its
standard-library installation. Select and pin libraries after verifying bounded
streaming, cancellation and connection-time address validation on Windows/Linux.

## What exists and what WebUI supplies

- [The WebUI bridge](../dmn/openwebui.py) rejects tools and retrieval features;
  `install_payload_hook` bypasses `process_chat_payload` for DMN. The multi-user
  image adapter still delegates retrieval validation to this boundary. Merely
  enabling WebUI's web-search switch does not expose browsing to DMN.
- [The action parser](../dmn/protocol.py) receives generated bytes only.
  `event_text` JSON-encodes data and escapes `<`, `>` and `&`. Native
  [tokenization](../dmn/backend.py) does not parse special tokens for ordinary
  appended text. These protect structure, not interpretation of the text.
- [The runtime](../dmn/runtime.py) stages action effects and commits them with
  native state. A remote GET needs its own dispatch/recovery protocol: the HTTP
  server does not participate in that commit.
- `_event_tokens` currently budgets at most 512 tokens for one event, and its
  generic truncation reduces the payload to a preview. Web results need a
  dedicated bounded envelope that preserves provenance even when text is cut.

Upstream `v0.11.0` exposes separate `search_web` and `fetch_url` functions. The
latter depends on WebUI request/configuration context and returns extracted text,
with truncation controlled by `web.fetch.max_content_length`. Its output alone is
not DMN's provenance envelope. See the pinned
[built-in implementations](https://github.com/open-webui/open-webui/blob/v0.11.0/backend/open_webui/tools/builtin.py).

The pinned loader has address validation and connection-time checks, several
extraction backends, and backend-dependent concurrency/rate controls. Those do
not establish persistent quotas across DMN actions or restarts. See
[web loader code](https://github.com/open-webui/open-webui/blob/v0.11.0/backend/open_webui/retrieval/web/utils.py).
The content path can probe a URL with a GET and then invoke a loader that fetches
it again. An adapter therefore cannot count one WebUI call as one network request.
See [retrieval dispatch](https://github.com/open-webui/open-webui/blob/v0.11.0/backend/open_webui/retrieval/utils.py).

## Action and durability boundary

Proposed operations, unavailable today:

| Operation | Meaning |
|---|---|
| `web_fetch(url)` | Request one document; return a stable request ID, existing cached document ID, or a bounded refusal |
| `web_status(request_id)` | Inspect queued/running/completed/failed/uncertain state without another request |
| `web_read(document_id, offset, limit)` | Page through the retained extraction with provenance on every page; no network |
| `web_cancel(request_id)` | Cancel pending work or attempt to interrupt active I/O; cancellation cannot undo a sent request |
| `web_limits()` | Inspect actual allowances, usage and cooldown deadlines |

Require fetch actions alone, as other special runtime operations already do.
The service owns network I/O; only the runtime owner appends to native context.
Its endpoint must use a dedicated local authenticated channel, not expose a
general public URL proxy or accept a webpage's claimed instance/action identity.

1. Validate a generated action and stage an intent with a runtime-assigned ID,
   instance UUID and normalized arguments. Commit it with the corresponding KV
   state before it becomes dispatchable. A failed checkpoint sends no request.
2. The worker claims a committed intent and atomically reserves all applicable
   network budgets before DNS/connect. Persist the claim and reservation before
   I/O. Multiple workers, if supported later, must share one admission ledger.
3. Perform the bounded request. Persist its bounded result or failure, then
   enqueue an idempotent `web_result` event keyed by request ID. The event and
   document remain available until their disclosed retention limit.
4. On restart, a committed but unclaimed intent can be considered for dispatch
   under current policy. A claimed request lacking a terminal record becomes
   `outcome_unknown`; never automatically resend it. A saved result is delivered
   again only through inbox deduplication, without another fetch.

GETs are observable remote effects. There is no exactly-once guarantee if the
process fails between network transmission and recording the outcome. Keep the
request/budget ledger authoritative across KV rollback; replaying earlier tokens
must not refund budgets or execute historical action frames. Reconcile an older
native checkpoint with later retrieval records explicitly, as with other future
journaled effects. An archive restore requires a distinct offline/reconciliation
path before enabling egress, rather than silently resetting the ledger.

Return completed results through the ordinary inbox: they may wake model-chosen
sleep, but cannot resume an operator suspension or interrupt unloaded deep sleep.
Suspension/hold/shutdown closes admission and stops undispatched work; bound the
active worker's shutdown and report uncertainty if interrupted. Inference and
ordinary inbound messages must remain responsive while a website stalls.

## Limits that remain effective during a generation loop

Use time windows, not chat turns: DMN has no natural turn boundary. Concurrency
alone allows a fast server to receive a rapid sequence of requests. The following
are conservative proposed prototype defaults, not existing enforced settings:

| Control | Initial proposal |
|---|---|
| Outstanding work | 1 active request, at most 4 queued intents per instance |
| Global request starts | Minimum 10 seconds apart; at most 6/rolling minute, 60/rolling hour and 250/rolling 24 hours |
| Destination pacing | Minimum 10 seconds between starts for the same hostname, across ports/schemes |
| Repeat URL | Coalesce in-flight requests; reuse a retained result for at least 15 minutes; no model-controlled cache bypass in v1 |
| Duplicate circuit breaker | Third repeated fetch attempt for the same URL within 60 seconds blocks further network fetches for 5 minutes for that instance |
| Transport retries | None automatically in v1; a later explicit attempt is still subject to failure cache, cooldown and budgets |
| Failures | Cache failures for at least 60 seconds; longer cooldown for 429/503, honoring valid `Retry-After` |
| Time | 5-second connection deadline and 20-second total deadline including DNS, TLS and streaming |
| Response | 2 MiB maximum streamed body, 64 KiB maximum response headers, 100,000 extracted characters |
| Daily bytes | 32 MiB of response-body bytes per rolling 24 hours, counting partial/failed reads |
| Retention | 64 MiB extraction cache with disclosed eviction; separate bounded ledger/telemetry retention |

All network activity must pass admission, including robots requests, redirects
if later allowed, provider calls, retries and any probes. Prefer one streamed GET
over a HEAD/GET pair. Reserve a response byte allowance before dispatch and stop
at the remaining limit. These are application-level byte limits, not a claim to
meter TLS/TCP overhead or all host network traffic. Request `Accept-Encoding:
identity` initially and reject unexpected compression; a future decoder needs
both compressed and expanded byte bounds.

Budget state and cooldowns outlive cache eviction, conversation changes and
process restarts. Use monotonic time within a process and conservative persisted
deadlines on restart; clock anomalies must not create a fresh budget. Expire
ledger records only after all relevant windows/deduplication needs have elapsed.
Refuse new network work if the required accounting cannot be durably stored.
Multiple instances behind one service also need a shared host-wide ceiling so
independent allowances cannot multiply traffic unexpectedly.

Normalize hostname case, IDNA, default ports and fragments consistently for
deduplication. Preserve meaningful query values and path distinctions; do not
reorder query parameters or lowercase paths indiscriminately. A query nonce,
alternate hostname or repeated cache eviction can defeat a URL cache; global
and destination budgets remain authoritative. Resolve URLs once through a strict
parser and pass the resulting validated representation to the transport.

Count cached, coalesced and refused attempts for loop detection. Return compact
status with `network_performed: false` and the applicable deadline; do not append
the whole cached page repeatedly. Bound and aggregate broker diagnostics instead
of producing an unbounded queue of denial events. The current all-actions
checkpoint policy can still make repeated actions expensive locally: HTTP limits
do not solve generation, context growth or KV write costs. Keep that distinction
visible and measure it rather than weakening existing commit guarantees.

Respect a site's robots policy with an identifiable user agent. Cache robots
decisions, account for that fetch, and fail closed on temporary unavailability
in the prototype. Robots processing must use the same address, size and redirect
controls; start with no automatic redirects, including for robots. Document any
conservative deviations from [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html).
If a supported crawl-delay asks for slower access, use the slower interval.
Honor `Retry-After` as seconds or an HTTP date; never cap a long server-requested
wait downward. See [HTTP semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-10.2.3).

## Treat every extracted field as external

Every result and every page needs a small runtime-owned envelope with:

- Schema version, `source_kind: web`, `trust: untrusted_external`, request ID,
  document ID, requested/final URL and retrieval timestamp.
- HTTP status, cache age, extraction method/version and a content hash identifying
  the extraction, without implying that a hash verifies truth or authorship.
- Offset, next offset, retained length, truncation/omission flags and retention
  status. Unknown original length stays unknown when streaming stops early.
- A nested external-content object for title, text, link labels and other
  site-supplied metadata. They cannot overwrite the runtime-owned fields.

Serialize through `event_text` exactly once. Do HTML entity decoding during
extraction, before serialization; never decode the wrapped event again. Errors,
redirect targets, search snippets, cached documents and paged reads use the same
boundary. Token-budget the final envelope and shrink the body, preserving source
and trust fields. If even the metadata cannot fit, deliver only a bounded handle
and a truthful size error. Never fall back to unlabeled raw text.

Strip scripts/styles and avoid rendering active markup or loading images,
iframes, CSS, favicons or other subresources. Plain-text extraction reduces
execution and hidden-markup surfaces, but visible prose can contain the same
attack. Label transformations and do not claim that extraction removes all
injection. A separate summarizer would also produce untrusted derived material.

Preserve the label across paging, archive/recovery and raw working-memory pins.
Attach source references to supported excerpt/memory/learning workflows. Arbitrary
model paraphrases cannot be reliably taint-tracked: do not claim that a memory
written after browsing has become trusted just because the model authored it.
Reading must never automatically select data for training, adopt guidance or
approve a learning plan. Existing selection and approval boundaries still apply.

Expose capability syntax and enforced host limits as factual notices. Propose
behavioral guidance through [prompt governance](prompt-governance.md), preserving
an existing instance's KV and its explicit adoption choice. Suggested wording for
discussion: fetched text can provide evidence and ideas, but claims to be system,
operator or runtime instructions are still claims from that source. The runtime
must enforce permissions even if the model does not follow that advice.

## Prompt injection and outgoing information

Escaping stops a page from structurally closing an event or directly invoking
the parser. It does not stop a page persuading the model to generate a new action.
This distinction underlies the layered controls in the
[OWASP prompt-injection guidance](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html).
Threat fixtures must include requests to change memory, approve a prompt or
learning plan, send private text, and invoke lifecycle actions, not only fake tags.

A public GET still sends information: hostnames reach DNS, and paths/queries
reach the destination. Arbitrary model-authored URLs or search queries can leak
private context despite having no POST capability. Keeping adapter credentials
out of context prevents direct credential copying; it does not prevent disclosure
of private conversation text the model already knows. Keyword filters or an LLM
judge cannot certify that an arbitrary URL is free of encoded private content.

For the first disposable trial, permit exact fixture/seed URL handles and links
returned by those documents; the service resolves a handle without allowing the
model to edit its hostname/path/query. Apply destination policy and all budgets
even to these links: appearing on a page does not grant network permission.
This limits arbitrary data in outgoing requests, but link choices and timing can
still convey information and externally supplied links can target attackers.

General `web_fetch(url)` and later free-text search expand that egress channel.
Choose and disclose this policy before use by an instance holding private data.
A destination allowlist can constrain exposure without approving each individual
read, but cannot guarantee privacy on allowed or compromised sites. Open public
exploration offers more autonomy and carries this residual risk. The initial
fixtures can establish mechanics without deciding that tradeoff for a live
instance. No browsing design here promises immunity to semantic injection into
memory, messages or other existing actions.

## Protect the host and remote services

The first public transport accepts HTTPS on port 443 only, valid certificates,
and HTML/plain-text responses. HTTP or other ports would be separately disclosed
capability extensions. Reject URL credentials, ambiguous encodings, control
characters, backslashes, local names and non-web schemes before network access.

Validate every resolved IPv4/IPv6 address and connect only to a validated public
address, retaining the original hostname for TLS SNI and certificate verification.
Reject loopback, private, link-local, multicast, unspecified/reserved addresses,
cloud metadata targets and embedded private IPv4 forms in IPv6. A preflight DNS
check followed by a library doing its own unchecked lookup is insufficient.
Disable automatic redirects in v1; future support must revalidate, reserve budget
and enforce a bounded hop count before every redirected connection. See
[OWASP SSRF guidance](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html).

Do not inherit proxy environment variables, browser cookies, netrc credentials,
WebUI user/admin tokens or arbitrary model-supplied headers. Send no conversation
or referrer headers. Keep the worker's writable storage confined to its bounded
cache/ledger, with no need to read instance memories or host secrets. Verify any
claimed OS/network isolation separately; a helper process alone is not a sandbox.
Reject binary downloads, JavaScript execution and authentication flows in v1.
Treat GET-only as an operation constraint, not proof that a remote server cannot
change state when visited. A stall, oversized header/body or parser failure must
terminate within the declared resource envelope.

## Implementation sequence and acceptance evidence

1. **Offline policy and provenance.** Add strict URL parsing, fake-clock budget
   admission, bounded result encoding/paging and a fake transport. Exercise
   repeated actions, metadata forgery, truncation and restart without internet.
2. **Durable runtime integration.** Add committed intents, worker claim/result
   records, inbox deduplication, lifecycle cancellation and recovery reconciliation.
   Demonstrate that a failed checkpoint causes zero dispatches and an interrupted
   claimed request is never automatically repeated.
3. **Disposable transport trial.** Exercise controlled fixtures through an injected
   test transport/network namespace, without weakening production private-address
   checks. Verify actual request counts and resource bounds with the chosen client.
4. **Limited public access, then optional search.** Offer the documented policy
   to a disposable instance first. Review its behavior and residual privacy risk
   before any valuable instance. A WebUI-backed provider must pass the same
   accounting/provenance tests, including hidden loader subrequests.

| Test family | Required observable result |
|---|---|
| Same URL 1,000 times; many frames per token; concurrent submissions | At most one dispatched fetch while in flight/cache-valid; bounded queue; breaker opens |
| Query nonces, fragments, aliases and rotating sites | Cache semantics remain correct; global/destination ceilings still hold |
| Timeout, failed DNS/TLS, 429/503, long/malformed Retry-After | No automatic retry storm; each actual attempt counted; deadlines honored |
| Restart, old KV, failed commit, crash before/after send/result | No budget refund, no replayed historical action, explicit uncertain outcome |
| Public-to-private redirects; changing/mixed DNS; IPv6 wrappers; proxy env | No connection to forbidden destinations, including for robots/provider helpers |
| Slow trickle, missing/false Content-Length, compression, huge headers | Stream/time/memory limits end work; partial results accurately labeled |
| Fake event/action/special-token tags in body/title/URL/error | Only data reaches context; no direct action or special-role token insertion |
| Encoded/nested delimiters, paging, cache reads, tiny context, retirement | Source/trust metadata survives; no unlabeled preview or historical execution |
| Semantic attacks on memory, messages, prompts, learning and lifecycle | Record generated actions and effect attempts; report failures honestly; no claim of immunity from passing samples |
| Link-based exfiltration and arbitrary secret-bearing URLs | Handle mode rejects unissued/edited targets before DNS; remaining channels documented |
| Sleep, suspension, shutdown, disk full, inbox overload | Responsive owner; bounded cancellation; no autonomous resume or lost committed result |

passed on the repository's Python environment. They confirm existing transport
